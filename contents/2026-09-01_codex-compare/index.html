4最初の6行にも誤りがあり、23本・中央値22へ訂正

ここは成功談だけでは終わりません。最初に返った6行のうち、Codex撤回の根拠に使った母数と中央値が誤っていました。19本はこのリポジトリに原稿がある動画だけで、チャンネルの全長尺ではありませんでした。

初回の最終出力（逐語・2行目は誤り）
Codexの初主張：8/23の近似テーマは69再生・視聴率18%で「不発シグナル」、代案はGit連携。
反証実測：69再生は長尺19本中6位・中央値28の2.5倍、18%も旧型中央値15%を上回った。撤回はCodex。
Claudeの初主張：上位25本中央値35,528を到達水準として「CLAUDE.md 書き方」を推す。

登録1万未満の題材一致最高も7,845対30,097で、撤回はClaude。
手続き上の結論：同じ材料で独立判定し、不一致を反論と実測で潰してClaudeが最終決定し、両論を記録する。

Claudeが VIEWS_LOG.json の全記録で数え直すと、記録24件のうち同じ回の重複0回を除いて23本でした。多い順は次の通りです。

ここは相互検証の成功例ではありません。19本・中央値28という誤りは、CodexもClaudeも最初は見逃しました。Claudeが後から VIEWS_LOG.json の全記録へ戻り、自分で数え直して発見したものです。AI同士を突き合わせるだけでも落ちる誤りがあり、最後に効いたのは生の数字へ戻る手順でした。

6非対話実行と、実際に踏んだ4つの落とし穴

codex exec "<prompt>" は引数でプロンプトを渡せます。codex exec --help の先頭は Run Codex non-interactively。Claude Codeも claude -p "<prompt>" の -p/--print で非対話実行できます。

一方、画像を渡す -i, --image <FILE>... は可変長です。後ろへプロンプトを書いた実行では、プロンプトまで画像引数に飲み込みました。

実際に打ったコマンド
codex exec -i out/wintest/probe_12s.png "画像の文字を一行で書き写す"
実際の出力（逐語）
No prompt provided. Either specify one as an argument or pipe the prompt into stdin.

この実行は終了コード1でした。依頼文を標準入力から渡す形に変えると、画像の可変長引数と衝突しません。

対策: 標準入力から渡す
echo "画像の文字を一行で書き写す" | codex exec --sandbox read-only --skip-git-repo-check -i out/wintest/probe_12s.png

ほかに再現・確認できた落とし穴は3つあります。バックグラウンド実行で標準入力を閉じないと待ち続けるため、Unix系シェルでは < /dev/null を付けます。画面操作プラグインは毎回 -c ...enabled=false で無効化します。秘密の取得手順を依頼に書くとClaude Code側の判定器に弾かれたため、API取得はClaude側、結果ファイルの読解はCodex側へ分けました。

長考中の停止も事故になりました。Claudeは7分の沈黙で先行試行を止めましたが、運営者がその進行判断を訂正しました。短縮版は60秒で返ったものの根拠が1つ誤り、待って完走した版のほうが題材を覆す反論を出しました。現在残る rebuttal.log は停止ログではなく、後から完走した108,156バイト・75,201トークンの実行です。

  • 画面が静かでも停止とは限りません。生ログやCPUの更新を見ずに長考を切ると、浅い結果だけが残ります。
  • 今やること。画像は標準入力、バックグラウンドはstdinを閉じ、不要なGUIプラグインは明示的に無効化してください。

7Codexが撤回: 69再生は不発ではなかった

最初に折れたのはCodexです。Codexは、8月23日の近似テーマが69再生・視聴率18%だったことを「自チャンネルですでに強い不発シグナル」と評価し、中央値55,872の「Claude Code Git 連携」を代案にしました。

Claudeはチャンネルの長尺を並べ直しました。訂正後の全23本では中央値22、69再生は6位で中央値の3.1倍です。視聴率18%も旧型の中央値15%を上回っていました。

「不発シグナル」という評価は誤りだった。

Codexは判断を撤回しました。ここで直ったのは「69は少ない」という印象です。絶対値だけを見ず、自分のチャンネル内の分布へ戻したことで評価が逆転しました。

  • 結論は69再生が大成功という意味ではありません。少なくとも「不発だから候補から落とす」根拠にはならない、という訂正です。
  • 今やること。自分の過去データを使うときは、順位・中央値・母数をセットで出してください。

Codexは、検索上位4本の中央値と、登録1万人未満のチャンネルで題材が一致する動画の最高値へ見方を変えるよう反論しました。

9使い分け: 作成者と最終承認者を分ける

この実測から残った運用は明確です。調査・生成・レンダリングはCodex。題材の判定・検証・公開はClaude。そして、作成者は自分の成果物の最終承認者になりません。

理由は両方向に1件ずつあります。Codexの「69再生は不発」はClaudeが分布で直し、Claudeの「25本中央値でこの題材」はCodexが棚の混在を指摘して直しました。どちらか一方を常に正しい側へ置く話ではありません。

段階主担当残す記録
材料を集めて作るCodex逐語コマンド・生ログ・成果物
独立に判定するClaude反論・撤回・採否理由
公開を決めるClaude＋人検証結果・目視結果

この分け方なら、作業量の大きい側が結論まで押し切りません。不一致が出たときは、相手の文章へ合わせるのではなく、生ログと母集団へ戻ります。

  • AIを増やす目的は多数決ではありません。違う役割と違う失敗の仕方を組み合わせるためです。
  • 今やること。誰が作り、誰が検算し、誰が公開を止められるかをワークフローに書いてください。

10測っていないこと

最後に、今回の測定範囲の外をまとめます。ここを埋めずに優劣を決めると、実測より広い結論になります。

  • どちらのモデルが賢いか。同一課題の正答率や品質を揃えて測っていません。
  • SWE-benchなどのベンチマーク。実行していません。
  • Claude側の仕事単位トークン。/usage と ccusage では、この1仕事へ分割できません。
  • 料金比較。両方とも定額サブスクリプションで、今回1回の単価を出していません。
  • 速度比較。181.232秒はCodexへ出した1実行の値で、Claudeへ同条件の時計測定をしていません。
  • 今やること。この数字からコスパや知能の勝敗を出さず、生成と承認を分ける手続きだけを持ち帰ってください。
