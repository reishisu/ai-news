1何を測ったか — 作り物ではなく、実際に埋まっていたバグ

AIレビューの実力を測る記事はたくさんありますが、多くはそのために作ったバグを使います。それだと「わざと分かりやすくした問題を見つけた」以上のことが分かりません。

この記事では、このリポジトリ（動画を作る自作ツール・約3,700行）に本当に埋まっていたバグ2件を差分に戻して測りました。どちらも2026年8月30日に実際に踏んで、直したものです。

実行環境（すべてこの機械での実測）
claude     2.1.251 (Claude Code)
python     3.10.6
git        2.52.0.windows.1
OS         Microsoft Windows 11 Pro 10.0.26200
PowerShell 7.6.5
CPU        AMD Ryzen 7 5800X (8コア16スレッド)
locale.getpreferredencoding() = cp932   ← ここが後で効きます

測り方は単純です。バグを戻した差分を作り、①静的解析（pyflakes）②AIレビュー（claude -p "/code-review"）の両方にかけて、何を見つけるか・いくらかかるかを記録しました。

2バグ1: 使っていない変数を参照していた

1件目は素直な NameError です。関数の中で n_slides という変数を使っているのに、その変数を作る行が無い、という状態でした。

バグのある状態（render_video.py の render_clip）
def render_clip(ctx, i, slide):
    ffmpeg, work, only = ctx["ffmpeg"], ctx["work"], ctx["only"]
    dirname, cat, total = ctx["dirname"], ctx["cat"], ctx["total"]
    # ここに n_slides = ... の行が無い
    cuts = slide.get("cuts") or []
    ...
    print(f"  slide {i + 1}/{n_slides} [実録] カット{n_cut}本 ...")

この関数は「実録の画面録画を動画に差し込む」処理で、実装されてから一度も呼ばれていませんでした。だから誰も気づかないまま残っていて、初めて使おうとした日に落ちました。しかも落ちるのは動画の書き出しが全部終わったあとです。

3バグ2: ロケール依存で落ちる（Linuxでは起きない）

2件目はもっと厄介です。Pythonで外部コマンド（ここでは ffmpeg）を呼んで出力を読む、というだけのコードです。

バグのある状態
run = subprocess.run([ffmpeg, "-i", str(path)], capture_output=True, text=True)
m = re.search(r"Duration: (\d+):(\d+):([\d.]+)", run.stderr)

text=True は「出力を文字列として受け取る」という意味ですが、何の文字コードで読むかは指定していません。この場合Pythonは、その機械の既定（ロケール）を使います。

環境既定の文字コード結果
Linux（開発時）UTF-8問題なし
日本語Windowscp932UTF-8の出力を読むと落ちる

しかも落ち方が悪質です。例外は出力を読むスレッドの中で握り潰され、run.stderr は None になって返ってきます。呼び出し側は「なぜか中身が空」という状態を受け取り、その次の行の re.search(..., None) で TypeError になります。本当の原因（文字コード）はどこにも出ません。

これは静的解析には見つけられません。字面としては完全に正しいコードで、問題は「実行する機械のロケール」という外部条件にあるからです。

4静的解析 — 0.27秒・0円・1件

まず pyflakes です。Pythonの定番の静的解析で、pip install pyflakes だけで入ります。

打ったコマンド
python -m pyflakes render_video.py
出力（実測）
render_video.py:3301:30: undefined name 'n_slides'
  -> 0.27 秒 / 0円 / 1件

バグ1は即座に、正確な行番号つきで出ました。0.27秒、料金は0円です。この速さと値段には、AIレビューは絶対に勝てません。

そしてバグ2については何も言いません。これは静的解析の欠陥ではなく、原理です。subprocess.run(..., text=True) は文法的にも型的にも正しく、問題は実行環境の側にあるからです。

5AIレビュー — 同じ1件と、出せないはずの1件

次に Claude Code のコードレビューです。/code-review は「いまの差分を見てレビューする」指示で、対話画面を開かずに -p で1回実行できます。

打ったコマンド
claude -p "/code-review" --allowedTools Bash Read Glob Grep --output-format json

バグ1についての指摘は、静的解析と同じ場所を指しつつ、影響まで書いてありました。

render_video.py:3301 — render_clip raises NameError: n_slides. （中略）Every kind:"clip" slide now crashes after doing all its synthesis and encoding work.

1回目の実行より（原文ママ）

「音声合成と書き出しを全部やったあとで落ちる」という部分は、静的解析には書けません。この関数が何をする関数なのかを読んで初めて言えることです。

6決定的だったのは「再現までやる」こと

この記事で一番驚いたのはここです。バグ2について、AIレビューは指摘しただけでなく、この機械で実際に再現しました。

locale.getpreferredencoding(False) is cp932 on this machine, so text=True alone decodes ffmpeg stderr as cp932 with errors='strict'. I reproduced it: an mp3 at a path with Japanese characters makes subprocess's reader thread die with UnicodeDecodeError: 'cp932' codec can't decode byte 0x86, the exception is swallowed inside the thread, and run.stderr comes back None.

1回目の実行より（原文ママ）

さらに、プロジェクト自身のBGMファイルを調べていました。

The project's own assets/bgm/houdou-times.mp3 already has Japanese ID3 tags — I confirmed its banner decodes to cp932 mojibake (繝輔Μ繝ｼ蝣ｱ驕薙ちイ繝ス, incl. private-use U+F8F0). Any tag bytes forming a cp932-illegal sequence kills the BGM step at the end of a full render.

1回目の実行より（原文ママ）

つまり「理屈の上では落ちうる」ではなく、「このプロジェクトのこのファイルで、フルレンダリングの最後に落ちる」と特定しています。これはコードを読むだけでは出せない指摘で、実際に手を動かせる道具（Bash）を渡してあるから出てきたものです。

7影響は6関数10箇所に広がっていた

私が「バグ2」と数えていたものは、実際には10箇所ありました。AIレビューはそれを全部たどって、それぞれ何が起きるかを分けて書いています。

場所関数起きること
:185media_secondsre.search(..., None) で TypeError
:2095measure_loudness同上。既存の if not m: return None の逃げ道が届かなくなる
:2127bgm_loop_wavBGMのID3タグで実際に落ちる

最後の行が地味に一番怖いところです。エラー処理のコード自体が落ちるので、本当の失敗理由が表示されずに消えます。

8誤検知は0件だった

AIレビューでいちばん怖いのは「見つけすぎ」です。何にでも文句をつけるなら、読むだけ時間の無駄になります。そこでバグを一切含まない差分を見せました。

見せたのは、エラーメッセージに「探した場所」を足すだけの変更です。動きは何も変わりません。

結果（実測・111.6秒・$0.8851）
No findings.

ただ「問題なし」と言ったのではなく、確かめたうえで言っていました。

I executed the function's failure path against relative, absolute, and ..-relative src values; the message renders correctly in all three and no TypeError/formatting error occurs on Path objects.

誤検知テストより（原文ママ）

さらに、気づいた小さな点を「findings には入れない」と自分で判断していました。

Only cosmetic nit (not reported as a finding): when src is absolute, ... the "探した場所" list prints the same path four times. Harmless — it does not affect resolution, only the diagnostic text.

同上（原文ママ）

この「指摘しない判断」ができるかどうかが、実務で使えるかの分かれ目だと思います。

9実験設計の穴を、レビューに見抜かれた

正直に書きます。誤検知テストは1回失敗しています。私の作り方が悪く、「バグを含むコミット」と「それを打ち消す未コミットの変更」が同時に存在する状態になっていました。

レビューはそれを自分で見抜いて、レビュー対象を選び直しました。

There is also an uncommitted change to that same file which is an exact revert of the commit (git diff main is empty). I reviewed the committed diff as the PR — the working-tree revert appears to be leftover from a previous run, not part of the change.

3回目の実行より（原文ママ）

「差し戻しは前の実験の残骸だろう」という推測まで当たっています。そのとおりでした。私はこの指摘を受けて、コミットの構造を作り直してから測り直しています（それが第8章の結果です）。

10時間と料金 — 4回の実測

同じ指示を4回実行しました。ばらつきは小さくありません。

時間は111〜247秒（2.2倍）、料金は$0.80〜$1.70（2.1倍）の幅がありました。深く調べた回ほど高くなります。3回目が突出しているのは、構文木まで見て「n_slides はグローバルでも引数でもない」と確かめていたからです。

一方で指摘の中身は安定していました。1回目と2回目は同じ2つの根本原因・同じ行番号を出しています。違ったのは再現の見せ方だけ（1回目はBGMのタグ、2回目は日本語を含む録画のパス）でした。

11使い分け — 結論

4回測って出た結論は、「どちらか」ではなく「両方、順番に」です。

静的解析（pyflakes）AIレビュー（/code-review）
所要0.27秒111〜247秒
料金0円$0.80〜1.70
未定義変数見つける見つける
環境依存の不具合原理的に不可再現つきで指摘
影響範囲の展開しない6関数10箇所
誤検知—0件

静的解析は毎回かける。0.27秒・0円なので、かけない理由がありません。実際、今回の NameError は私自身がこれで見つけました。

AIレビューは「動かないと分からない類」に効きます。ロケール・OS・実データの中身に依存する不具合は、字面を見るだけの道具では出せません。今回それを、実際に手を動かして再現するところまでやりました。

同じことをやるなら、この2コマンドです。

同じ計測をやる2コマンド
# 1. 静的解析（毎回・0円）
python -m pyflakes 対象.py

# 2. AIレビュー（差分がある状態で）
claude -p "/code-review" --allowedTools Bash Read Glob Grep --output-format json

--allowedTools に Bash を入れているのが要点です。入れないと「再現して確かめる」ができません。今回いちばん価値のあった指摘は、全部この道具から出ています。

12やっていないこと

この記事で測っていないことを、はっきり書いておきます。

  • 他の静的解析との比較をしていません。測ったのは pyflakes だけです。ruff や mypy なら別の結果になります
  • 他の言語・他の規模で測っていません。対象はPython 1ファイル・約3,700行です
  • 見逃しの母数を測っていません。「埋まっていた2件を見つけた」であって、「このリポジトリに他にバグが無い」ことは確かめていません
  • 誤検知は1パターンしか試していません。良性の変更1件に対して0件だった、というだけです
  • 料金は4回のうち3回ぶんです。1回目は --output-format json を付け忘れて記録していません
  • 他のAIレビューと比べていません。GitHub Copilot や CodeRabbit との比較はしていません
