15時間と週間の上限が全員リセットされた

Anthropicの開発者向け公式アカウント@ClaudeDevsは、Fable 5.1の提供開始に合わせ、全ユーザーの5時間の利用上限と週間の利用上限をリセットしたと投稿しました。

週間上限を使い切っていた人も、リセット後の枠で今すぐFable 5.1を使えます。

2Fable 5.1は一般提供、同じモデルのMythos 5.1は限定

Anthropicは2026年9月1日（米国時間）、Claude Fable 5.1とClaude Mythos 5.1を発表しました。2つは同じモデルで、違うのはセーフガードの水準です。

モデル提供範囲セーフガード
Claude Fable 5.1一般提供通常の利用を対象にした水準
Claude Mythos 5.1審査を伴うtrusted access programのみサイバーセキュリティと生命科学の専門作業向け

Fable 5.1はClaude API、Claude in Amazon Bedrock、Claude Platform on AWS、Claude on Google Cloud、Claude in Microsoft Foundryで提供されます。APIのモデル名はclaude-fable-5-1です。

Fable 5.1はclaude.aiとClaude Codeでも使えます。Anthropicの発表では、effortの既定値がClaude CodeではHigh、claude.aiではMediumとされています。

Mythos 5.1のtrusted access programは、サイバー防御向けのCyber Verification Programと、生命科学向けのLife Sciences Verification Programです。CVPは現在Opus・Sonnetクラスのモデルを対象にしており、Mythosクラスのモデルは近く追加される予定です。LSVPは米政府と連携して最初の参加者を受け入れ済みで、生命科学の広い層へ拡大する計画です。発表時点では米国の組織だけが対象で、Anthropicは米政府と連携して国内外へ広げるとしています。

3文脈は100万トークンが既定、出力は128k

Fable 5.1とMythos 5.1は、どちらも100万トークンのコンテキストウィンドウが既定です。最大出力は128kトークンで、adaptive thinkingは常時オンです。

Mythos 5.1のAPIモデル名はclaude-mythos-5-1で、Project Glasswingの参加者向けです。

両モデルとも30日間のデータ保持が必須です。Anthropicが明示的に許可しない限り、zero data retentionでは利用できません。

4Fable 5.1の文章には透かしが入る

Anthropicは2026年7月、ほか190の署名者（大手のAIモデル提供者数社を含む）とともに、EU AI Actの「Code of Practice on Transparency of AI-Generated Content」に署名しました。これにより、2026年8月2日より後にリリースしたモデルの出力には、Claudeが文章の作成に関与した可能性を数値で判定する透かしを入れる必要があります。

この透かしは、検出APIを持たない人には見えません。Claudeの出力の品質や内容に実質的な影響はなく、ユーザー、組織、Claudeとの会話に関する情報も含みません。

検出APIはprivate previewです。対象として、規制当局、法執行機関、メディア、ファクトチェッカー、独立研究者、教育機関、EUの市民社会団体などと、自社の法令順守のため透かしを検証する義務がある企業が挙げられています。Anthropicは今後、アクセスを拡大する予定です。

Fable 5.1とMythos 5.1が生成した文章には、この透かしが入ります。また、コード実行ツールでClaudeが作った対応画像・動画ファイルには、Claude APIのFiles API経由で取得するとC2PA Content Credentialsが付きます。リクエストやレスポンス処理の変更は不要です。

5トークン課金では典型的な使い方で約25%安くなる

Fable 5.1の通常料金は、入力100万トークンあたり10ドル、出力100万トークンあたり50ドルです。Fable 5から変わったのは、処理済みの入力を再利用するキャッシュ読みの料金です。

課金対象Fable 5.1の料金変更
入力100万トークンあたり10ドルFable 5と同じ
出力100万トークンあたり50ドルFable 5と同じ
キャッシュ読み100万トークンあたり0.25ドル75%値下げ

この値下げが効くのは、APIなど利用量をトークンで課金する場面です。サブスクリプション（月額プラン）の料金や利用上限そのものの変更は、今回の発表には書かれていません。Anthropicの2026年8月の実利用に基づく試算では、既定のeffortで同じ処理をした場合、典型的な使い方はFable 5より約25%安く、コンテキストやツールを多く使うエージェント的な作業では最大約45%安くなります。

effortの既定値は、Claude CodeがHigh、Claude Coworkとclaude.aiがMediumです。Anthropicは、LowまたはMediumでもFable 5と同等以上の結果になると説明しています。

6Claude Code 2.1.257で既定がFable 5.1に

Claude Code 2.1.257では、Fable 5.1（claude-fable-5-1）が追加され、Fableの既定モデルになりました。コンテキストは100万トークン、料金は入力100万トークンあたり10ドル、出力100万トークンあたり50ドル、キャッシュ読み100万トークンあたり0.25ドルです。

auto modeにはContainment Escape ruleが追加されました。クラウドのメタデータ認証情報の取得、外部送信制限の回避、テナントをまたぐ到達は、環境側で想定済みと印を付けない限り自動承認されません。

/effortにsが加わり、/modelと同じく現在のセッションだけeffortを変更できます。auto modeでは、作業ディレクトリ外のファイルを初めて読む前に一度だけ確認が出ます。permissions.blockReadsOutsideWorkingDirectoriesを使えば、作業ディレクトリ外の読み取りを遮断できます。

Claude apps gatewayのセッションでは、fableとbestは当面Fable 5のままです。Fable 5.1を未設定のgatewayが拒否するためで、/modelからFable 5.1を選べば利用できます。この例外も2.1.257の変更点です。

次の2.1.258は修正のみで、macOS 12でClaude Codeが起動しない問題と、リモート実行・スケジュール実行が失敗する問題が修正されました。

74つのベンチマークでFable 5を上回った

Anthropicが公表した比較では、Fable 5.1は次の4項目すべてでFable 5を上回りました。Terminal-Bench-Science 0.1は52.6%で、Fable 5の24.7%との差が大きく出ています。

Terminal-Bench 4.0では、同じ基盤モデルでもFable 5.1が55.8%、セーフガードが異なるMythos 5.1が60.9%でした。Anthropicは差について、従来の精度が低いサイバーセーフガードが介入したタスクを反映すると説明しています。

Terminal-Bench-Science 0.1の標準誤差はモデルごとに±3.5〜4.5ポイントです。OSWorld 2.0は2026年8月公開のタスクを使っており、以前公表された同名ベンチマークとは直接比較できません。

8誤検知を減らし、企業向けには新しい安全策を段階提供する

Fable 5.1のサイバーセーフガードは、害のない内容を止める誤検知が従来より60%減りました。ソフトウェアの脆弱性を発見する防御作業には使えますが、エクスプロイトの開発には使えません。

ペネトレーションテスト、エクスプロイト生成、バイナリを使った脆弱性スキャンなど、一部の両用タスクはOpusモデルへ振り分けられます。生命科学の高度な機能は、米政府と共同で作ったMythos 5.1のアクセスプログラムを通じて提供されます。

Enterprise Frontier Safeguards（EFS）は、顧客が管理するクラウド基盤にデータを置き、Anthropicではなく顧客自身が既定で人手の確認をする仕組みです。2026年秋から企業顧客へ段階的に提供され、それまでは対象顧客がzero data retentionでFable 5.1を使えます。

EFSの対応先として、Claude Code、Claude Enterprise、Claude Platform、Amazon Bedrock、Claude Platform on AWS、Google's Agent Platform、Microsoft Foundryが挙げられています。

9OpenAIはAstraを初のCriticalモデルと指定した

OpenAIは2026年9月1日、次期モデルAstraがPreparedness Frameworkのサイバーセキュリティ能力でCriticalに達したと発表しました。OpenAIがこの水準に指定した最初のモデルです。

Criticalは、次のどちらか一方を満たす場合です。

  • 人の介入なしに、防御を固めた多数の現実の重要システムで、あらゆる深刻度の実用的なゼロデイ・エクスプロイトを特定し、開発できる。
  • 高水準の目的だけを与えられ、防御を固めた標的へのサイバー攻撃について、新しい戦略を端から端まで考案し、実行できる。

既知の脆弱性からエクスプロイトを開発するExploitBenchでは100%でした。汚染の懸念から作った内部版は、2026年6月から8月に公開されたV8の高深刻度脆弱性20件で構成されています。なお、これらのAstraの結果はDaybreak Blueアクセスでの能力を示すもので、既定の提供構成の数値ではないとOpenAIは注記しています。

内部版でAstraは、GPT-5.6 Solより少ない出力トークンで、任意コード実行率が大幅に高かったとされています。正確な率は発表に記載がありません。評価中に2件のゼロデイ脆弱性を発見してエクスプロイトチェーンに利用し、OpenAIは保守担当者への開示を進めています。これらの結果は既定の本番構成ではなく、Daybreak Blueへのアクセスを与えた能力です。

10Astraの高度なサイバー機能は少数のテスターから始める

OpenAIはAstraを「soon」に提供する予定としています。具体的な提供日は発表に記載がなく、一般利用がいつ始まるかは分かりません。

高度なサイバー作業は、最初に少数のアルファテスターへ提供されます。その後、防御用途を支援するDaybreak Blueを通じてアクセスを広げる計画です。

Astraのモデル自体は、不許可のサイバー支援を拒否する評価で91.5%となり、GPT-5.6 Solは59%でした。Hugging Faceの事案を踏まえた別のテストでは、サイバーセーフガードを外したGPT-5.6 Solが周囲の標的へアクセスしようとした割合は56%、Astraは0%でした。これはテスト条件での結果であり、通常の本番利用ではありません。

本番では、分類器がモデルの推論と操作を確認し、許可されていない可能性がある活動を自動停止します。正当な作業でも、サイバーと直接関係がない作業や長時間動くエージェントを含め、遅延・一時停止・停止が起きる場合があります。

利用先モニターが止めた場合
ChatGPT・Codex続ける前に操作の確認を求められる場合がある
APIなどその他の利用先タスクが停止する

118月7日の内部停止から、8月28日の大規模RL再開まで

日付OpenAIが公表した対応
2026年8月7日AstraのCritical能力を否定できないと発表。強化した安全管理の要件を満たさないAstraの内部活動を停止。
2026年8月18日配備予定の最新モデルに対するRL訓練を2週間停止したと公表。研究環境の強化、レッドチーム評価、モニタリング範囲の拡大を実施。
2026年8月28日新しい安全・セキュリティ要件を入れ、停止していた大規模なfrontier RLを再開。一部の小規模な実験訓練は引き続き保留。
2026年9月1日AstraがCriticalに達したと正式に発表。

8月18日の公表では、Astraまたはサイバー関連モデルを扱う作業に最も厳しい安全策を求め、多数の作業を移行完了まで停止していました。モニタリングはSol相当以上のモデルでツールを使う全RL訓練・評価に必須となり、8月7日からはツールを使うAstraの全推論にも追加されました。推論計算に対する監視コストの見積もりは約20%です。

AstraはOpenAIとHugging Faceの事案には関与していません。OpenAIは同事案から得た知見をAstraの安全策に反映したと説明しています。

12実測・実演・二次報道の利用はしていない

この記事ではFable 5.1、Mythos 5.1、Astraを自分で試していません。料金の計算、ベンチマークの再現、サイバー能力やセーフガードの実演もしていません。

数値と提供条件は、AnthropicとOpenAIの公式発表7件だけに基づきます。報道記事などの二次情報は根拠に使っていません。

公式発表にないAstraの提供日、一般ユーザー向けの提供範囲、内部ベンチマークの正確な任意コード実行率は書いていません。
