Claude CodeのMCPサーバーが読み込まれたか確かめる — addが成功しても繋がっていない

MCPサーバーを入れたのに、AIがそのツールを使ってくれない。原因は入れ方ではなく、確かめ方にあることがあります。この記事のログはすべて Claude Code 2.1.251 での実測です。行を省いた箇所は「(中略)」と書きました。
▶ この記事を動画で見る（11分）ずんだもん×四国めたんの掛け合い・実演つきの解説
⏱ 自分の設定を見るのは約3分 全部コピペOK 依存ライブラリなし

⭐ 3行で言うと

  1. claude mcp add は、存在しないファイルを指しても成功します。打ち間違えたパスでも Added ... と出ます。「追加できた」は「設定を書いた」という意味しかありません。
  2. 繋がったかどうかは claude mcp list が初めて教えます。ここで √ Connected になって、やっとモデルから呼べます。実際に呼ばせて確かめました。
  3. ただし一覧の「承認待ち」は、一覧だけの話でした。.mcp.json のサーバーは ⏸ Pending approval と出たままなのに、claude -p からは普通に呼べました。公式ドキュメントにもそう書いてあります。
先に4語だけ意味
MCPAIに外部の道具（GitHub、Notionなど）を繋ぐための共通の決まりごと。Model Context Protocol の略
MCPサーバーその道具の側。AIから呼べる関数を並べて待っているプログラム
stdio繋ぎ方の1つ。サーバーを自分のPCで起動して、その入出力で会話する（この記事はこれだけ扱う）
スコープ設定をどのファイルに書くか。local / project / user の3つ

1「追加できた」は「繋がった」ではない

存在しないファイルを指しても、addは成功する

検証用に、依存ライブラリのいらない最小のMCPサーバーを1つ書きました。ツールは hello 1つだけです。全文は _labs/ にあります。

まずわざとファイル名を打ち間違えて登録します。hello.py を helo.py と打ちました。

わざと間違えて追加する
$ claude mcp add demo -- python3 helo.py
Added stdio MCP server demo with command: python3 helo.py to local config

helo.py は存在しないのに、成功しました。ここで作業を終えると、あとで「入れたのに動かない」になります。

一覧を見ると、初めて分かります。

claude mcp list（間違ったまま）
$ claude mcp list
Checking MCP server health…

demo: python3 helo.py - × Failed to connect — CONNECTION_CLOSED: Connection closed

この記事の端末ログには、幅40桁に収まらない行があります。枠の中を右へスクロールしてください。サーバーのパスは短くしてから測り直しましたが、Failed to connect — CONNECTION_CLOSED… の部分は claude 自身が出す文言です。こちらで縮めると書き換えになるので、そのまま貼っています。

パスを直して入れ直すと、通りました。

直したあと
$ claude mcp remove demo
$ claude mcp add demo -- python3 hello.py
$ claude mcp list
Checking MCP server health…

demo: python3 hello.py - √ Connected

この √ と × は、この環境の端末での見え方です。公式ドキュメントでは ✔ と ✘ で書かれています。

公式ドキュメントも、add と list の役割をはっきり分けています。

Claude Code Docs「MCP」Server status より（原文）
claude mcp add confirms a successful add by printing an Added ... line, which means the configuration was written. claude mcp list then shows a health status next to each server it lists, such as ✔ Connected, ! Needs authentication, or ✘ Failed to connect.

「which means the configuration was written」がすべてです。add が保証するのは、設定ファイルに書けたことだけです。

一覧が通ったら、モデルからも本当に呼べた

一覧の √ Connected は、claude が接続を試した結果です。では、AIから見えているのか。実際に呼ばせました。

モデルにツールを呼ばせる
$ claude -p "mcp__demo__hello を name=めたん で呼ぶ" \
  --allowedTools "mcp__demo__hello"
応答: 「こんにちは、めたん」

サーバーが返す文字列がそのまま出ました。一覧が √ Connected なら、モデルからも呼べます。ここまでは素直な話です。

2同じサーバーでも、置き場所が違うと片方だけ繋がらない

スコープを変えて、同じサーバーをもう1台足した

MCPサーバーの設定は、3か所のどれかに書かれます。-s で選びます。

スコープ書かれる場所誰のものか
local（既定）~/.claude.json自分だけ。いまのプロジェクトのみ
project.mcp.json（プロジェクト直下）チーム全員。gitに入れて共有する
user~/.claude.json自分だけ。全プロジェクトで使える

さっきの demo（local）を残したまま、まったく同じサーバーを team という名前で project スコープに足しました。

project スコープで追加
$ claude mcp add -s project team -- python3 hello.py
Added stdio MCP server team with command: python3 hello.py to project config

できた .mcp.json は、demo と同じ中身を指しています。

.mcp.json
{
  "mcpServers": {
    "team": {
      "type": "stdio",
      "command": "python3",
      "args": [
        "hello.py"
      ],
      "env": {}
    }
  }
}

同じコマンド、同じファイル、同じツール。違うのは書かれた場所だけです。一覧を見ます。

claude mcp list（2台）
$ claude mcp list
Checking MCP server health…

team: python3 hello.py - ⏸ Pending approval (run `claude` to approve)
demo: python3 hello.py - √ Connected

片方だけ「承認待ち」になりました。中身は1文字も違いません。

理由は公式ドキュメントに書いてあります。.mcp.json は git で配られてくるファイルなので、他人が書いたコマンドが黙って動くと困る、ということです。

Claude Code Docs「MCP」Project scope より（原文）
For security reasons, Claude Code prompts for approval in interactive sessions before using project-scoped servers from .mcp.json files. To reset those approval choices, run claude mcp reset-project-choices.

承認するには claude を対話で起動します。この記事の実測は無人実行の環境で取ったので、承認ダイアログそのものは出していません。対話側の挙動は上の引用が根拠で、自分では確かめていません。

3承認待ちのまま、claude -p からは呼べた

一覧の表示と、実際に読み込まれるかは別だった

ここが今回いちばん意外だったところです。demo（local）を消して、承認待ちの team だけにしました。

承認待ちの1台だけにする
$ claude mcp remove demo
$ claude mcp list
Checking MCP server health…

team: python3 hello.py - ⏸ Pending approval (run `claude` to approve)

この状態で、そのツールを呼ばせてみます。設定は1文字も変えていません。

承認していないのに呼んでみる
$ claude -p "mcp__team__hello を name=ずんだもん で呼ぶ" \
  --allowedTools "mcp__team__hello"
「こんにちは、ずんだもん」という応答が返ってきました。

呼べました。承認していないのにです。念のため、承認の記録が付いていないことも確かめました。

承認の記録は空のまま
$ python3 -c "...(~/.claude.json を読む)"
enabledMcpjsonServers = []
disabledMcpjsonServers = []

これは不具合ではありません。公式ドキュメントに明記されています。

Claude Code Docs「MCP」Project scope より（原文）
In claude -p runs, Agent SDK sessions, and cloud sessions, Claude Code can't show that prompt: it loads project-scoped servers without asking.

承認ダイアログは画面に出すものなので、画面のない実行経路では出せません。出せないので、聞かずに読み込みます。

一覧の側にも、同じことが別の言い方で書いてあります。

Claude Code Docs「MCP」Server status より（原文）
The statuses in this list report a configuration decision rather than a connection attempt, so Claude Code prints them without connecting to the server:

つまり ⏸ Pending approval は接続を試した結果ではありません。√ Connected だけが実際に繋いだ結果で、承認待ちは「対話で起動したらこうなる」という予告です。

  • CI・自動実行では、承認待ちのサーバーも動きます。「一覧が承認待ちだから止まっている」と思っていると、実際には読み込まれています。
  • 逆に、対話で使えていたものがCIで止まることは、この理由では起きません。止まるとしたら別の原因です。
  • 他人の .mcp.json を git pull したときは、中身を読んでください。対話なら聞かれますが、自動実行では聞かれません。

4締め出したいときに効いた2つ

どちらも、この環境で実際に効いた

「自動実行では聞かれない」なら、聞かれなくても入らないようにする方法が要ります。公式ドキュメントが挙げている手段のうち、2つを実際に試しました。

1つ目は --strict-mcp-config。--mcp-config で明示的に渡したサーバー以外を全部無視します。

--strict-mcp-config を付ける
$ claude -p "mcp__team__hello を呼ぶ。無ければツールが無いと言う" \
  --allowedTools "mcp__team__hello" \
  --strict-mcp-config
mcp__team__hello というツールはありません。

2つ目は disabledMcpjsonServers。プロジェクトの .claude/settings.json に名前を並べます。

.claude/settings.json
{
  "disabledMcpjsonServers": ["team"]
}
拒否された状態
$ claude mcp get team
team:
  Scope: Project config (shared via .mcp.json)
  Status: × Rejected (see disabledMcpjsonServers in settings)

この状態で呼ばせると、今度はツールがありませんでした。

拒否中に呼んでみる
$ claude -p "mcp__team__hello を呼ぶ。無ければツールが無いと言う" \
  --allowedTools "mcp__team__hello"
mcp__team__hello というツールは存在しません。

ここでもう1つ、引っかかりやすい挙動が出ました。拒否したサーバーは、一覧から丸ごと消えます。

拒否中の claude mcp list
$ claude mcp list
No MCP servers configured. Use `claude mcp add` to add a server.

.mcp.json は残っているのに「1台も設定されていません」と出ます。公式ドキュメントは、この状態が get にだけ出ると書いています。

Claude Code Docs「MCP」Server status より（原文）
✘ Rejected (see disabledMcpjsonServers in settings): a .mcp.json server that a disabledMcpjsonServers entry rejects. Claude Code shows it only in claude mcp get <name>.

なのでlist が空でも、設定が無いとは限りません。名前が分かっているなら claude mcp get <名前> で見てください。

最後の1行が、この記事の結論です。一覧は「対話で起動したらどうなるか」を見せています。CIや自動実行で使うつもりなら、その経路で1回呼ばせるまで確認は終わりません。

今回試していないこと
  • 対話セッションは踏んでいません。無人実行の環境なので、承認ダイアログを出す経路そのものがありません。
  • stdio 以外は試していません。HTTP / SSE のサーバーと、! Needs authentication の状態は再現していません。
  • 実在のMCPサーバーには接続していません。全部、自分で書いた最小のサーバーです。
  • user スコープと reset-project-choices は実行していません。承認済みの状態を作れなかったので、戻す対象がありませんでした。
