8/18〜19(米国時間) ⚠ 障害(復旧済み) AWS

AZ(アベイラビリティーゾーン)は、リージョンの中で独立した電源・ネットワークを持つデータセンター群のことです。AWSは欧州(ロンドン)リージョン eu-west-2 に4つ目のAZ「eu-west-2d」を追加しました。

AWS What's New の原文
With this new Availability Zone (eu-west-2d), customers can distribute applications across four Availability Zones in eu-west-2

その直後に障害報告が出ます。

AWS Health Dashboard の原文
Between August 18 5:00 PM and August 19 11:00 AM PDT, we experienced elevated errors launching EC2 instances in a newly launched Availability Zone (euw2-az4)

日本時間では8/19 9:00〜8/20 3:00です。既存の稼働中インスタンスとリソースには影響がありませんでした。

  • 踏んだのは「AZを自動で選ぶ」構成だけ。原文は「Workflows that automatically get a list of Availability Zones in the Region via the DescribeAvailabilityZones API and then attempt to launch new instances or create resources in the new Availability Zone may encounter errors.」——AZ一覧をAPIで取得して展開する自動化が、デフォルトサブネットのまだ無い新AZを引き当てて失敗しました。サブネットIDを明示指定する構成は影響を受けません。
  • 「新AZの追加」は今後も必ず来るイベント。自分のリージョンにAZが増えた日、AZ一覧を動的に使うIaCやオートスケールの自動化が同じ前提(デフォルトサブネットがある・自分のサブネットを作ってある)を満たすか、一度洗っておく価値があります。これは筆者の運用上の意見です(参考文献参照)。
  • 補足：表記の注意。障害報告のAZ表記はeuw2-az4(AZ ID)、告知のAZ名はeu-west-2dで、公式が両者を明示的に対応付けた文書はありません(この期間にeu-west-2で新設されたAZは1つです)。AZ名はアカウントごとに割り当てが変わるため、障害報告はAZ IDで書かれます。
  • 今やること。eu-west-2を使っているなら、DescribeAvailabilityZonesでAZ一覧を取って展開する自動化が無いか確認する。あるなら、サブネットIDを明示指定するか、デフォルトサブネットの有無を先に確かめる処理を足す。使っていなければ対応は不要。

androidx.webkit 1.17.0 — loadUrl()の後継navigate()とHTTPキャッシュ容量の制御が入った

8/12公開 新機能 WebView

androidx.webkitは、WebViewをアプリから制御するJetpackライブラリです。1.17.0の目玉は WebViewCompat#navigate() です。

androidx.webkit 1.17.0 の原文
Introduces a modern replacement for WebView#loadUrl.

履歴エントリの置き換え、追跡できるNavigationオブジェクトの返却、状態保存・復元をまたいだヘッダーの一貫した持ち回りが挙げられています。

ただしnavigate()はまだ実験的(Opt-in)なAPIです。@RequiresFeatureが付いており、実行時にWebViewFeature.isFeatureSupported()で端末側のWebView実装が対応しているかを確かめてから呼ぶ必要があります(未対応環境ではUnsupportedOperationException)。ライブラリを1.17.0に上げただけでは「使える」とは限りません。

公開は8月12日で、このセクションの遡り枠(1週間)を1日超えていますが、これまでの号で扱っておらず、WebViewの読み込みAPIが世代交代する話なので載せます。

  • HTTPキャッシュの容量を制御できる。「HTTP Cache Quota Control (Profile#getHttpCache): Provides APIs to inspect and adjust profile-level HTTP cache quotas」——静的コンテンツの多いアプリでキャッシュ量を調整し、未使用時のディスク占有を減らせます。事前接続をキューに積むProfile#enqueuePreconnect()も入りました(こちらも実験的アノテーション付き)。いずれもisFeatureSupported()の実行時チェックが前提です。
  • Lintが「レンダラクラッシュ処理の未実装」を警告するようになる。「Adds an AndroidX lint check that flags missing onRenderProcessGone implementations when a custom WebViewClient is attached」——カスタムWebViewClientを使っているアプリは、依存を上げるとビルド時に新しい警告が出る可能性があります。
  • 今やること。すぐの移行は不要。loadUrl()からnavigate()への移行を試すなら、実験的APIである前提でisFeatureSupported()の分岐を必ず入れる。依存更新の際は新Lintルールの警告に対応する(レンダラクラッシュ時のonRenderProcessGone実装)。
