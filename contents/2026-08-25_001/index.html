Slackの@Claudeは、呼ばれなくても返信する — 切れるのはチャンネル単位だけ

8/23 更新 Slackに入れている人 public beta Claude Tag

Claude Tag は、Slackのチャンネルに @Claude を置く仕組みです。組織の共有アカウントとして動き、接続先やスキル（Claudeに教える手順書。次の項目で詳しく書きます）は管理者が決めます。

なお、まだ正式版ではなく public beta（試験公開）の段階です。

最初に知っておくべきなのは、呼んでいない発言にも返信することがある点です。しかも既定でそうなっています。

Claude Tag ドキュメント（返信の既定）
The setting is on by default, so a channel
Claude was just added to replies without
@-mentions from the start.

つまり、チャンネルに入れた瞬間から「たまに勝手に喋る」状態で始まります。どのくらい喋るかは、Claudeがチャンネルの履歴と記憶から判断します。

問題は止め方です。設定は Respond automatically ひとつですが、置き場所に制約があります。

同ドキュメント（設定の置き場所）
Each channel has its own copy of the
setting, and there is no workspace- or
organization-wide version. To make Claude
mention-only across many channels, turn it
off in each one.

50チャンネルに入れたなら、50回切ることになります。導入を決める前に、入れるチャンネルを絞るほうが早いという判断材料です。

切り方は3通り。どれも同じ設定を変える

1. Slackで直接頼む。@Claude only respond in this channel when someone @-mentions you directly. と書くと、Claudeが変更を確認して返します。この変更はそのチャンネル全員に効きます（自分だけ静かになるのではありません）。

2. Claudeの返信のフッターにある Configure リンクを開き、Respond automatically を切る。

3. 管理者は claude.ai/admin-settings/claude-tag の Slack タブから、該当スコープの Advanced で切る。スコープとは、Claude Tag の設定をまとめて掛ける単位です（どのチャンネル群に効かせるかの区切り）。

なお、既にClaudeが入っているスレッドは別扱いです。チャンネル全体を切ってもそのスレッドだけは返信が続くので、スレッド内で個別に頼む必要があります。

もう1つ、ClaudeのTeam / Enterpriseプラン（法人契約）で使っている場合は、旧版の廃止が待っています。従来の「Claude in Slack」（Claude Code in Slack を含む。管理画面では Legacy と表示されます）は、各自のアカウントで動く仕組みでした。これがClaude Tagに置き換わります。

移行ドキュメントの警告文
The earlier Claude in Slack app, shown as
Legacy in admin settings, is being
deprecated; check with your account team
for the cutover date. After that date,
channels still set to Legacy stop
responding until the scope's Claude Tag
version is set to New.

移行日は公表されていません。「契約窓口に聞け」と書いてあるだけです。日付が公開資料に無い以上、当媒体からも書けません。

切り替えで何が消えるかは、はっきり書かれています。新版は自分の接続を1つも持たずに始まります。

切替後どうなるか
Slackアプリと @Claude の名前そのまま。入れ直しは原則不要
DM従来どおり各自の claude.ai アカウントで動く
GitHubリポジトリなどの接続引き継がれない。管理者が Access bundle（Claudeに渡す接続先をまとめた管理者向けの設定）に足すまで、コードの依頼をしても読みにいけるリポジトリが無い
過去のデータ移行されない
  • 入れる予定があるなら。入れるチャンネルを絞ってから始める。あとから全体を静かにする手段がありません。
  • 法人契約の管理者なら。契約窓口にLegacyの移行日を聞き、移行前にGitHub接続の張り直しを段取りしておく。

Claudeが自分のスキルにプルリクを出す仕組みが文書化された — マージは人がやる

8/25 更新 Team/Enterprise の管理者 public beta Claude Tag

この節の2件のうち、対象期間内（8月24日5:00〜8月25日5:00 JST）に更新されたのはこちらです。Claude Tag 配下は期間内に7ページ動いており、そのうち管理者向けの skills repository のページを取り上げます。新設されたのか書き換えられたのかは、公開情報からは判別できません（更新日しか取れないため）。

スキルとは、道具の使い方や手順を書いた指示のまとまりです（Claude Code と同じ形式）。これをGitリポジトリに置くと、次のことが起きます。

スキルのリポジトリのドキュメント（冒頭）
Put your org's Claude Tag skills in a git
repository with auto-sync, grant Claude
write access, and Claude can open pull
requests to improve its own skills from
what it learns in channels.

チャンネルで指摘されたことを、Claude自身がスキルの修正案としてPRにする、という流れです。ただし勝手には出しません。頼まれたときだけです。

同ドキュメント（PRを出す条件）
Claude won't open skill PRs unprompted.

そしてマージは人の手です。「Every skill change reaches channels only after a human approves the merge」と明記されています。マージするとリポジトリが自動で同期され、次のスレッドから新しいスキルが効きます。

用意するもの（公式の手順どおり）

1. private か internal のGitHubリポジトリを作る（internal は法人向けGitHubの「組織内だけに公開」）。中身は Claude Code のプラグインマーケットプレイスの形にします。マーケットプレイスといっても売買ではなく、Claudeが読み込むプラグインの目録の置き方の決まりで、ルートの .claude-plugin/marketplace.json がその目録です（プラグインごとに1フォルダ）。publicのリポジトリは選べませんので、使いたければ private にフォークします。

2. claude.ai/admin-settings/plugins の Plugins ページで Add plugins → Sync from GitHub。Sync automatically は既定のままにします。

3. Access bundle の Repositories タブに、そのリポジトリを足す（Claudeが書き込めるようにするため）。

4. 同じ bundle の Plugins タブで、使うプラグインを1つずつオンにする（既定は全部オフ）。

なお、自分のプロジェクトの .claude/skills/ に置いたスキルは、Slack側ではそのプロジェクトのリポジトリを渡したスレッドの中でしか効きません。どのチャンネルでも効かせたいなら、上のスキル専用リポジトリに置きます。

  • 使っているなら。スキルを1つのprivateリポジトリに寄せるところから始める。あとから「Claudeに直させて人がレビューする」に切り替えられます。
  • 今やること。Claude Tagを使っていなければ対応は不要。使っているなら上の1つ。

MinIOのコミュニティ版はもう更新されない — Laravel Sail の minio はそこを指している

8/24 公開 提供終了 Laravel Docker

きっかけは Docker が8月24日に出した記事です。中身は同社の有償サービスの案内ですが、その前提になっている事実のほうが読者に効きます。

MinIOは、ファイルを出し入れする置き場（オブジェクトストレージ。AWSのS3が代表）を手元に立てられるソフトです。S3と同じAPIで喋るので、ローカルでS3の代わりに立てる用途でよく使われています。

Laravel Sail（Laravel公式のDocker開発環境。docker-compose.yml を用意してくれる仕組み）にも、起動できるコンテナの1つとして入っています。そのMinIOのコミュニティ版が、もう保守されていません。

MinIO リポジトリ README（冒頭）
> [!NOTE]
> **THIS REPOSITORY IS NO LONGER MAINTAINED.**

同じREADMEには、配布のしかたも書いてあります。

MinIO リポジトリ README（配布のしかた）
The MinIO community edition is now
distributed as source code only. We will no
longer provide pre-compiled binary releases
for the community version.

ビルド済みの配布も止まっています。使いたければ自分でソースから作れ、という状態です。

では、いま Laravel Sail を使っている人は何を動かしているのか。実際に見に行きました。

Sail が指すイメージと、その最終 push
$ curl -s .../sail@1.x/stubs/minio.stub \
    | sed -n '1,2p'
minio:
    image: 'minio/minio:latest'

$ curl -s .../minio/minio/tags/latest \
    | python3 -c '...'
tag      latest
pushed   2025-09-07

latest という名前ですが、2025年9月7日から一度も更新されていません。約1年前のバイナリです。

落ち着いて見てほしいのは、これは今日壊れる話ではないことです。Sail の minio は手元の開発環境で動くもので、本番のS3とは関係ありません。動いているものが急に動かなくなるわけでもありません。

効いてくるのはこれからです。今後 MinIO に脆弱性が見つかっても、このタグには修正が来ません。「latest を引いているから最新のはず」という前提だけが崩れています。

呼び名やっていること

論文の要旨（該当箇所）
Augmenting one agent's capabilities or
context cannot resolve this architectural
mismatch; intelligence must instead be
distributed across specialized agents and
organized at the system level.
