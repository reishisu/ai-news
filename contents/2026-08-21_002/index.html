Claude Codeのセッション間メッセージは、有効にする操作なしで動いている — 止め方と、Bedrockでは使えないこと

2.1.224 / 8月7日 ⚠ 既定の挙動 Claude Code

Claude Codeは2.1.224で、別々に開いているセッション同士がメッセージを送り合う機能を入れました。相手を探すListAgentsと、送るSendMessageの2つです。

読者にとっての要点は機能そのものではなく、これが有効化の操作なしで動いていることです。公式ドキュメントがそう書いています。

公式ドキュメント（cross-session messaging）の原文
Cross-session messaging requires Claude Code v2.1.224 or later and runs on macOS and Linux. When a session meets the requirements, messaging is on with nothing to enable.

届くかどうかは、送る側と受け取る側の権限モードの組み合わせでメッセージごとに決まります。設定としての既定値はありません。

受け取る側送る側が通常送る側が権限確認を飛ばす設定
通常（権限確認が出る） そのまま届く 承認待ちで保留
権限確認を飛ばす設定 承認待ちで保留 そのまま届く

つまり普通に使っているセッションは、届いたメッセージをそのまま受け取ります。受け取ったあとの扱いも書かれています。

公式ドキュメント（配達後の扱い）の原文
Once delivered, the message counts toward usage like a prompt you type
  • アイドルなら新しいターンが始まる。ターンの実行中に届いた場合は、ツールの実行を中断せず、ツール呼び出しの合間に読まれます。
  • AWS経由では、そもそも機能が無い。Amazon Bedrock・Claude Platform on AWS・Google CloudのAgent Platform・Microsoft Foundry 経由では提供されません。ネイティブWindowsも対象外です（WSL 2の中のLinuxは対象）。
  • 2.1.236でnotify_when_idleが加わった。同じマシンの別セッションに「次にアイドルになったら1回だけ知らせて」と頼めます。opt-in・1回限り・ポーリングなしで、購読は12時間で失効します。送る側と受け取る側の両方が2.1.236以降である必要があります。
止め方の設定を見る
settings.json（受信も送信も止める）
{
  "permissions": {
    "deny": ["SendMessage", "ListAgents"]
  },
  "crossSessionInbound": "refuse"
}

上から順に潰してください。0 / 3

今やること。macOS / Linux で2.1.224以降を使い、同時に複数のセッションを開いているなら、既に話しかけられる状態です。受け取りたくなければcrossSessionInboundをrefuseにし、送信も止めるならSendMessageとListAgentsをdenyに足す。Amazon Bedrock経由で使っているなら、この機能は提供されないので対応は不要です。

PyPI / Anthropic

Anthropic Python SDKが1.0.0に — Bedrockはregion未指定だと起動時に落ちる

8/21 4:58 JST ⚠ 破壊的変更 AWS

PythonからClaudeを呼ぶ公式ライブラリanthropicが、0.125.0から1.0.0に上がりました。0番台から1.0への変更なので、互換性のない変更が入っています。

AWSを使っている読者に一番効くのはBedrockです。これまではリージョンが見つからないと警告だけ出してus-east-1で動いていたのが、構築した時点で例外になります。

移行ガイド MIGRATION.md の原文
`AnthropicBedrock` / `AsyncAnthropicBedrock` used to log a warning and silently fall back to `us-east-1` when no AWS region could be found. They now raise a `ValueError` at construction time instead.

気付かないうちにus-east-1で動いていた構成は、上げた瞬間に起動しなくなります。落ちるのは良いことで、意図しないリージョンで課金され続けるより先に分かります。

直し方（どれか1つ）
AnthropicBedrock(aws_region="ap-northeast-1")

# または環境変数
export AWS_REGION=ap-northeast-1
  • 探す順番も増えている。1.0.0は aws_region 引数 → AWS_REGION / AWS_DEFAULT_REGION → 指定したaws_profileのboto3設定、の順で解決します。移行ガイドには「以前はプロファイル引数がリージョン検索で無視されていた」と書かれています。
  • Pythonの最低版が3.9から3.10へ。3.9の環境ではpipが1.0.0を選ばず、0.125.0までしか入りません。Pydanticはv1・v2とも引き続き使えます。
  • HTTP層がhttpxからhttpx2へ。古いhttpxのクライアントを渡すとTypeErrorになるので、黙って壊れることはありません。ただしrespx / pytest-httpx / vcrpyやOpenTelemetry・Sentryの計測は、動き続けるのにSDKの通信だけ見えなくなります。起動時にhttpx2.alias_httpx()を呼びます。
  • temperature / top_p / top_kがメソッドから消えた。APIから消えたのではなく引数から消えただけなので、必要ならextra_body={"temperature": 0.2}で素通しします。
  • 旧Text Completions APIが削除。client.completions.create()とHUMAN_PROMPT / AI_PROMPTが無くなりました。Messages APIへ移します。

今やること。すぐ上げる必要はありません。requirements.txtにanthropicをバージョン指定なしで書いているなら、次のビルドで勝手に1.0.0が入るので、まずanthropic<1で固定して落ち着いて移行する。Bedrockを使っているなら、上げる前にaws_regionかAWS_REGIONが明示されているかだけ先に確認する。

Claude Codeの公式運用ガイド — 会話の途中でモデルを切り替えると、会話全体が送り直しになる

8月14日 公式ガイド Claude Code

Anthropicが8月14日、Claude Codeのセッション運用ガイドを公開しました（著者 Lydia Hallie）。changelogにもXにも出ない型の一次資料で、当サイトが落としていたものです。

中身は「トークンの単価を決めるもの」と「セッションが送る量を決めるもの」の2部構成です。一番効くのは、キャッシュが壊れるタイミングでした。

公式ガイドの原文（送られる順番）
The cache has to match from the very start of the request forward, and requests always go out in the same order: tool definitions, then the system prompt, then the conversation (with CLAUDE.md at the front of it).
  • モデルごとに別のキャッシュがある。会話の途中で/modelを切り替えると、次のターンで会話全体が満額で送り直しになります。plan モードを出入りするたびにモデルが変わるopusplanも同じです。
  • キャッシュの有効期間はサブスクで1時間、APIキーで5分。ターンのたびに時計が戻ります。席を離れる前に/compactしておくと、キャッシュが生きているうちに要約できて安く済みます。
  • 直前の数ターンが要らないだけなら/rewindのほうが安い。末尾を切るだけなので手前はキャッシュに残ります。/compactは会話全体を書き換えるので必ずコストがかかります。
  • ファイルは名前で書かず@で指す。メッセージに直接添付されるので、読みに行く呼び出しが1回、探す必要がある場合は検索も省けます。
  • 出力は入力のおよそ5倍の価格。1トークンずつ生成するためGPUの占有時間が長い、と説明されています（200トークンの応答は200回のモデル実行）。

今やること。新しいセッションで/contextを1回だけ実行し、CLAUDE.mdとMCPのツール定義がどれだけ場所を取っているか見る。そのうえで、タスクを変えるときは/clear、モデルと effort は着手前に決めて途中で変えない、席を離れる前に/compact、の3つを習慣にする。

DeepSeek HarnessはMITの開発者プレビュー — 公式発表の3時間前にBSDからMITへ切り替わっていた

8月13日 新機能 OSS

ハーネスとは、モデルの周りを固める土台のことです。エージェントのループ、道具の呼び出し、セッションの記録、サンドボックス、承認、UI。Claude Codeでいう「Claude Code側」の部分がそれにあたります。

DeepSeekが自社のハーネスをMITライセンスで公開しました（コマンド名はdsh）。ただし開発者プレビューで、READMEが大文字で警告しています。

リポジトリ README の原文
DeepSeek Harness is currently in _developer preview_ and is iterating rapidly. **THERE WILL BE COMPATIBILITY-BREAKING CHANGES.**
  • 「DeepSeek版のClaude Code」ではない。モデルアダプタ自体がプラグインで、設定からAnthropic・OpenAI・Bedrock・Vertex・Azure・Codex・任意のOpenAI互換エンドポイントを挿せます。公式は「エージェントループ自体を含め全部がプラグインで、設定から差し替えられる」と書いています。
  • ライセンスは途中で変わっている。npmの版ごとのメタデータを全10版たどると、8月10〜12日に出た0.0.1-rc.xの3版はBSD-3-Clauseで、0.1.0-rc.2（8月13日 09:48 UTC）以降がMITです。公式発表（同日 13:02 UTC）の3時間13分前に切り替わっていました。
  • Plan modeは実行を止める機能ではない。公式リファレンスが「soft guidance（緩い誘導）」と明記し、サンドボックスと承認ポリシーは独立して働くので別々に設定が要る、としています。

今やること。対応は不要。乗り換えの判断をする段階ではありません。確認は1つだけで、ロックファイルに@deepseek-ai/dshの0.0.1-rc.xが入っていないか見る。入っていればBSD-3-Clauseのままなので、社内の使用許諾表に写しているなら書き換えが要ります。本番とCIには入れないこと。

正体を明かさないモデル「Ox Alpha」がOpenRouterに — 無料だが、プロンプトは提供者に保持される

8/21 5:04 JST 新モデル OpenRouter

OpenRouterとは、いろいろな会社のAIモデルを1つの窓口から呼べる仲介サービスです。そこに今朝、作った会社を明かさないモデル「Ox Alpha」が載りました。モデル一覧APIの登録時刻は日本時間8月21日 5:04、公式Xの告知は6:02です（当サイトの朝5時の号の、対象期間の直後でした）。

OpenRouter 公式Xの告知（全文）
🥷 New stealth model: Ox Alpha

Ox Alpha is a frontier model built for efficient coding, sustained agentic work, and real-world production use.

- 1M token context window
- Text, image, and video input

Try it now and share feedback to improve the model!
  • 中身。文脈は1,048,576トークン、最大出力131,072トークン。テキスト・画像・動画を入力できます。価格は入力・出力とも0ドル（プレビュー中）。
  • 提供者は匿名。モデルページには「このプレビューの間は匿名でいることを選んだ第三者の提供者が開発・運営している」とあります。誰が作ったかは公表されていません。
  • 無料の終了時期は書かれていない。「1週間」と書く記事も出回っていますが、公式ページにその記載はありません。確認できないので当サイトは書きません。

読者が判断に使うべきなのは、性能の噂ではなくデータの扱いです。モデルページに明記されています。

モデルページの原文（データの扱い）
Prompts and completions for this model are retained by the provider and are not used for training

つまり、送ったプロンプトと出力は匿名の提供者の手元に保持されます。「学習には使わない」は提供者の申告で、誰の申告かは分かりません。

今やること。個人の実験で試すのは自由です。ただし業務のコード・顧客情報・秘密情報は送らないこと。無料で高性能なものには理由があり、この場合の対価は「誰か分からない相手にプロンプトが渡り、保持される」ことです。会社で使うかは、この1点だけで判断できます。
