Claude Codeの週次利用上限「+50%増」は8月31日まで — 以降は元に戻る可能性がある

8/18 告知 ⚠ 利用上限 Claude Code

週次の利用上限とは、各プランに設定された「1週間あたりに使える量」の枠です。その枠を一時的に50%増やしている措置の期限が、8月31日まで延びました。

@ClaudeDevs 2026年8月18日の投稿(原文)
We're extending the 50% increase to weekly Claude Code limits through August 31.

We hope to make this a permanent change to our plans, but strong demand for our models means that capacity may be tight over the coming weeks. We'll keep you posted as things develop.

つまり「恒久化を目指すが約束はできない」という位置づけです。9月1日以降も続く保証はありません。

  • 対象は「週次」の上限で、プランはPro / Max / Team / Enterprise。短時間(5時間)ごとの枠ではなく、週単位の枠が対象です。原文の「weekly Claude Code limits」に沿った記載で、当サイトでは実際の枠の数値は測っていません。
  • これは8月18日の告知で、当時取り上げ損ねていた続報です。この種の上限・料金の変更は、changelogや公式ブログではなくX(旧Twitter)が初出になることがあります。今回も@ClaudeDevsの投稿のみでの告知でした。日付が過去である点を踏まえて読んでください。
  • 今やること。週次の枠まで使い切る使い方をしているなら、8月31日という期限を頭に入れておく。9月に入って上限の体感が変わったら、この延長が切れた可能性を最初に疑う。恒久化されるかは「未定」なので、続報を待つ。

Claude Code 2.1.237 — 結論を先に出す出力スタイル「Concise」が追加

8/20 8:57 JST 新機能 Claude Code

出力スタイルは、Claudeの返答の書き方を切り替える設定です。新しく「Concise(簡潔)」が組み込みで追加されました。

CHANGELOG 2.1.237 の原文
Added a built-in "Concise" output style: Claude leads with results and skips preamble and narration, while doing the work just as thoroughly. Select it under Output style in /config.

結果から先に書き、前置きと途中経過のナレーションを省きます。「作業そのものは同じだけ丁寧にやる(doing the work just as thoroughly)」と明記されているので、省くのは説明の量であって作業の中身ではありません。

  • 選び方。/configのOutput styleから選択します。返答の前置きが冗長だと感じていた人向けの、体感が変わる設定です。
  • 公開時刻。npmレジストリの記録で2.1.237は2026-08-19T23:57Z(日本時間8/20 8:57)。同じ版で「LLMゲートウェイ/カスタムbase URL利用時のプロンプトキャッシュ」の不具合も直っていますが、これは該当環境だけの修正です。
  • 今やること。対応は不要。返答が長いと感じるなら/configで「Concise」を試す、というだけの任意の設定です。

Claude Code 2.1.238 — .mcp.json のヘッダー生成コマンドに、フォルダの信頼承認が必要になった

8/21 3:01 JST ⚠ 仕様変更 Claude Code

MCPサーバーとは、Claude Codeに外部のツールを足す仕組みです。その設定ファイル .mcp.json には、接続時のHTTPヘッダーを作るコマンド（headersHelper）を書けます。短命なトークンをその場で発行させるための機能です。

2.1.238から、このコマンドはフォルダの信頼ダイアログを承認するまで走りません。非対話の claude -p でも同じです。

CHANGELOG 2.1.238 の原文（信頼の要求）
MCP `headersHelper` in a project `.mcp.json`, and inline MCP servers in project or `--add-dir` agent files, now require that folder's trust dialog to have been accepted (also under `claude -p`)

あわせて、そのコマンドに認証情報の環境変数が渡らなくなりました。原文は「継承した認証情報の環境変数なしで走る」と書いています。

CHANGELOG 2.1.238 の原文（認証情報の扱い）
MCP `headersHelper` from a project `.mcp.json`, plugin, or agent file runs without inherited credential env vars; user, managed and claude.ai-scope helpers now run from the Claude config dir

同じ版で、手が覚えている操作も2つ変わりました。

操作2.1.237まで2.1.238から
フルスクリーンで Ctrl+L / Cmd+K 2回続けて押すと /clear が走った 常に再描画だけ。2回押しの /clear は廃止
claude mcp list / get 無効にしたサーバーにも接続して疎通確認 接続せず ⊘ Disabled と表示するだけ
  • 非対話で動かしているなら先に確認。信頼ダイアログの承認は claude -p でも必要です。CIやスクリプトからプロジェクトの .mcp.json を使っている場合、そのフォルダが承認済みかどうかで結果が変わります。
  • プラグイン導入時に確認が入る。カタログの headersHelper は、実行するコマンドを表示したうえで claude plugin install/update が [y/N] を聞きます。自動化しているなら -y を渡します。
  • この項目は当日中に追記しました。npmでの公開は2026-08-20T18:01Z（日本時間8/21 3:01）でしたが、朝5時の編集時点ではCHANGELOGに2.1.238の記載が無く、dist-tags.latest も2.1.237のままでした。中身を確認できないものは書かない方針（本サイトの規律）に従って保留し、記載が出たあとに追加しています。
  • 今やること。.mcp.json に headersHelper を書いているプロジェクトがあるなら、更新後に一度そのフォルダを開いて信頼ダイアログを承認しておく。書いていないなら対応は不要で、Ctrl+L の2回押しで /clear されなくなったことだけ覚えておけばよい。
