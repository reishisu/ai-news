1常駐しているのは名前と説明だけだった

「スキルを増やすとコンテキストを食う」は、半分だけ当たっている

スキルを1つ作ると、次に必ずこう思います。「便利だから10個20個入れたい。でも全部読み込まれたら重いのでは」。

測れます。claude plugin details が、常駐ぶんと呼び出しぶんを分けて出してくれます。ここでは mattpocock-skills という公開プラグイン（設計を質問攻めにして詰めるスキル集。25個入り）で叩きました。

claude plugin details（25件中7件を抜粋）
$ claude plugin details mattpocock-skills
Projected token cost
  Always-on:   ~1,609 tok   added to every session

Per-component (rounded)
  component                      always-on  on-invoke
  ask-matt                             ~40      ~3.8k
  diagnosing-bugs                      ~70      ~2.8k
  grill-with-docs                      ~50        ~20
（中略）
  grill-me                             ~30       < 20
  grilling                             ~60       ~610
  wait-what                            ~30        ~90
  writing-for-agents                   ~50      ~3.7k

この記事の端末ログは横に長いので、スマホでは枠の中を右へスクロールしてください。列の幅は claude 側が決めていて、こちらで詰めると数字を書き換えることになるため、そのまま貼っています。

左の always-on が常駐、右の on-invoke が呼んだときに増えるぶんです。25個ぜんぶ入れても常駐は約1,609トークンでした。上に抜き出した7件はどれも30〜70トークンです（残る18件は表に出していないので、全部がこの範囲とは言えません。1,609から抜粋7件の330を引いて18で割ると、残り18件の平均は約71になります）。

一方 writing-for-agents は呼ぶと約3,700トークン増えます。常駐約50トークンの、およそ74倍です。この差が「本文は呼ぶまで読まれない」ということです。

公式ドキュメントにも同じことが書いてあります。

Claude Code Docs「Skills」より（原文）
In a regular session, skill descriptions are loaded into context so Claude knows what's available, but full skill content only loads when invoked.

（このNoteはこのあと「サブエージェントに前もって積む場合は別で、起動時に本文まで入る」と続きます。上はふつうのセッションの場合です。）

つまり数を増やすこと自体のコストは小さい。「入れるだけで重くなる」を心配して絞る必要はありません。ここまでは安心していい話です。

2その説明には予算があり、超えると削られる

前回の結論には、上限があった

前回、同じ質問を60回投げて分かったのは「フォルダ名と description は、2つで1つの説明文」でした。どちらかが「いつ使うか」を語っていれば呼ばれ、両方が黙っていると落ちます。

実際、説明を雑にしてもフォルダ名が release-check なら10回中10回呼ばれました。名前を memo-1 に変えた瞬間、同じ説明で10回中1回まで落ちました。

その説明が、増えると勝手に短くされると公式ドキュメントに書いてあります。

Claude Code Docs「Skills」より（原文）
…The listing always contains every skill name, but if you have many skills, Claude Code shortens descriptions to fit the listing's character budget, which can strip the keywords Claude needs to match your request. The budget scales at 1% of the model's context window. When the listing overflows, Claude Code drops descriptions starting with the skills you invoke least, so the skills you use most keep their full text.

読み替えるとこうなります。予算は文字数で数えます（さっきの1,609はトークン数なので、この2つは直接くらべられません。だから次に出てくる /doctor が要ります）。

  • 名前は必ず残る。一覧から消えるわけではないので、/名前 と打てばいつでも動きます。
  • 削られるのは説明のほう。2つで1つだった説明文の、片方だけが残ります。
  • 削られる順番は使用頻度。よく使うものは残り、めったに使わないものから説明を失います。

つまり「たまにしか使わないが、そのときは自動で呼んでほしい」スキルが一番弱いということです。四半期に1回のリリース手順のようなものが該当します。使わないから説明を削られ、削られたから呼ばれず、呼ばれないからますます削られます。

そして削られたあと、呼ばれるかどうかはフォルダ名だけにかかります。前回の「名前をケチるな」は、予算対策でもあったわけです。memo-1 や utils のような名前は、削られた瞬間に何も語らなくなります。

Q. スキルを40個入れたら、めったに使わない release-check が自動で呼ばれなくなりました。/release-check と打つとどうなるでしょう?

正解は「ふつうに動く」。落ちたのは説明だけで、名前は一覧に残っています。「手で呼べば動くのに自動では呼ばれない」という状態は、予算あふれのサインのひとつです。

あふれているかどうかは /doctor で見られる

近いところまでは /context で見えます。いま何にどれだけトークンを使っているかを出すコマンドで、その中に Skills という行があります。対話画面向けですがこの記事を書いている環境でも動いたので、実際に測りました。

claude -p "/context"（出力から抜粋。Skills の表は23行）
**Tokens:** 61.4k / 1m (6%)
| Skills | 3.7k | 0.4% |
（中略）
### Skills

| Skill | Source | Tokens |
|-------|--------|--------|
| startup-hook-skill | User | ~90 |
| design | Built-in | ~340 |
| dataviz | Built-in | ~380 |
（中略）
| init | Built-in | ~20 |
（以下略）

23個で 3.7k トークン、コンテキスト窓の0.4%でした。1個あたりは init の約20から dataviz の約380まで19倍の開きがあります。説明が長いスキルほど重い、というだけの話です。

ただしこの0.4%と、予算の1%は直接くらべられません。予算は文字数で、この表はトークン数です。しかもドキュメントによれば、この Skills 行は予算を適用したあとの値なので、あふれたかどうかはこの数字からは分かりません。あふれの判定は /doctor のほうです。

広げ方・空け方も書いてあります。こちらは自分では試していませんので、書いてあることとして読んでください。

  • あふれの判定。/doctor が一覧の費用と、内訳の上位を出します。
  • 広げる。設定ファイル（~/.claude/settings.json など）に skillListingBudgetFraction を 0.02（2%）のように書きます。
  • 空ける。使わないものを skillOverrides で "name-only" にすると、説明なしで並びます。ただしプラグインのスキルには効きません（そちらは /plugin 側で管理、とドキュメントにあります）。
  • 手で書かなくてよい。/skills の一覧で選んで Space、Enter で保存できます。

もうひとつ。前回の記事で「勝手に呼ばれるのを止める1行」として紹介した disable-model-invocation: true は、公式ドキュメントの表で Description not in context（説明は常駐しない）とされています。一覧に説明が載らない以上、予算も空くはずです — ここは書いてある事実からの推論で、ドキュメントが「予算が空く」と明言しているのは skillOverrides の "name-only" についてだけです。

前回は「事故る手順を止める」目的で紹介しましたが、手で呼ぶと決めているスキルは、止めておくほうが他のスキルのためになるということになります。書く場所は SKILL.md の先頭、--- で囲まれた部分です。

残したいスキルの側でできることも、同じ段落に書いてあります。

Claude Code Docs「Skills」/ 同じ段落の続き（原文）
You can also trim the `description` and `when_to_use` text at the source: put the key use case first, since each entry's combined text is capped at 1,536 characters regardless of budget.

つまり説明は先頭から使われる。長く書くより、一番よくある使いどころを1文目に置くほうが、削られたときに生き残ります。

3増やす前の確認項目

この4つだけ見ておけば、増やしても静かに壊れません

タップでチェックできます。 0 / 4

🎉 全部できた！

前回の記事は「1個作る」話でした。今回は「増やす」話です。増やすこと自体は軽い（25個で約1,609トークン。1個あたりは説明の長さ次第）一方で、増やすと説明が削られて、前回測った条件が崩れる。ここだけ押さえておけば大丈夫です。

同じ名前のスキルがぶつかったときにどちらが動くか、動かないときのエラーの見分けかたは、次の2本にあります。

前回の記事（名前の衝突もこちら） Claude Codeのスキルの作り方 — 自動で呼ばれる条件を60回測った 入れ方でつまずいたら grill-me / grill-with-docs の導入手順 — セットアップ完了まで
