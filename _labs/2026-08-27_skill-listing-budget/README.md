# `/context` の Skills 行を測る

記事: `contents/2026-08-27_skill-listing-budget/`

## 何を確かめたか

公式ドキュメントは「スキル一覧の説明には、コンテキスト窓の1%という文字数の
予算がある」と書いている。**では自分の環境はいまどうなっているのか**を出す
手段として `/context` があるので、実際に叩いて Skills の行を見た。

あわせて、**`/context` が対話画面でなくても通るか**を確かめた。
記事の初稿では「`claude -p` では実行できなかった」と書いていたが、
**これは誤りだった**（検証で反証された）。実際には `-p` で通る。

## 動かし方

```bash
./run.sh          # claude -p "/context" を叩いて context.txt を作る
```

## 分かったこと（2026-08-27 JST の実行）

| | 値 |
|---|---|
| スキル数 | 23 |
| Skills の行 | 3.7k トークン / コンテキスト窓の 0.4% |
| 1個あたり | 約20（`init`）〜 約380（`dataviz`）。19倍の開き |

- **この 0.4% と、予算の 1% は直接くらべられない。** 予算は文字数、
  この行はトークン数で、単位が違う
- しかもドキュメントによれば Skills の行は**予算を適用したあとの**値なので、
  あふれたかどうかはこの数字からは分からない。あふれの判定は `/doctor`

## 実行環境

- 実行日: 2026年8月27日 (JST)
- Claude Code 2.1.247
- Linux x86-64 のコンテナ（`ai-news-video` リポジトリ上で実行）

## 注意

- **数字はこの環境のもの。** 記事の他の測定（実験4・実験5）で使った
  25個入りプラグインとは**別物**。突き合わせないこと
- `context.txt` は Skills の表と、それに関わる2行を抜き出したもの。
  行頭の `4:` `15:` は、元の出力での位置を示すために残している
