## 確かめたこと

1. 日数の決め打ち（7日）で「止まっている枝」を探すと、実データで検出0件になる
2. 同じ枝を、リポジトリ自身の履歴から出した85%点（SLE）で見ると要確認1件になる
3. 日単位の停滞は、日時を固定した検証用リポジトリ（合成データ）でしか測れなかった
4. 「検出0件」は健全・しきい値ズレ・スクリプト故障の3つで同じ見た目になる

## 注意（記事にも書いた筆者ルール）

- `MIN_N = 5`（標本5件未満ならSLEを出さない）は筆者の定数。Kanban Guide に5件という数字は無く、
  ガイドは逆に「履歴が無ければ当て推量でよい（a best guess will do）」と書いている
- `DAYS=7` は比較用に筆者が置いた決め打ち値。「7日が一般的」という資料は見つからなかった
- `flow_signals.py` が「中央値」と表示するのは nearest-rank の50%点。標本数が偶数だと真の中央値とずれる
- 「静止時間（最終コミットから現在まで）」は Kanban Guide に無い、筆者が足した指標
