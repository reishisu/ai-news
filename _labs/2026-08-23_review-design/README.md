# レビューで何を機械に任せられるか（実測）

記事: `contents/2026-08-23_review-design/`

## 確かめたこと

レビューで指摘したい欠陥を14件仕込んだファイル(`orders.py`)に、
既製の静的解析3種と、自作の規約チェッカーを当てて、何件が機械側で
落ちるかを数えた。**「機械 vs 人」ではなく「どこまで機械に降ろせるか」**
を測るのが目的。

## 動かし方

```bash
pip install ruff mypy bandit
./run_all.sh            # 出力は output.txt と同じ
python3 house_rules.py orders.py
```

## ファイル

| ファイル | 中身 |
|---|---|
| `orders.py` | レビュー対象。欠陥14件を仕込んである |
| `defects.md` | 仕込んだ欠陥の一覧と、どれが捕まったか |
| `house_rules.py` | 自チーム規約を機械に落とした3ルール(AST) |
| `narrow.py` | 出力を表示幅37桁に折り返す(文字は変えない) |
| `run_all.sh` | 4種をまとめて実行 |
| `output.txt` | 実行結果(記事に貼ったものと同一) |

## 実行環境（2026年8月23日 JST）

- Python 3.11.15 / ruff 0.15.8 / mypy 1.19.1 / bandit 1.9.4
- 出力は `narrow.py` で表示幅37桁に折り返している(記事の幅380pxに合わせるため。文字は変えていない)
- ruff は `--select E,F,B`、mypy は既定設定、bandit は既定ルール

## 結果

- 既製3種で 9/14。bandit は **0件**
- 自作の規約チェッカーを足して 12/14
- 残る2件は D10(権限チェック漏れ)と D12(境界が仕様と逆)。
  どちらも**正解がコードの外(仕様)にある**

## 注意

- **PHP版は作れなかった。** この環境から github.com が403で、
  composer が phpstan の dist を取得できない。言語をPythonにした
- 仕込んだ欠陥は実際のコードより密度が高い。**件数の比は
  「機械が何割」を一般化する根拠にはならない**。
  分けて考えるための材料として読むこと
