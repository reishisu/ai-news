# video.json（読み上げ原稿）の書き方

毎朝のデイリーセッションが、記事と一緒に `contents/<記事>/video.json` を書く。
このファイルが動画の設計図で、`_render_video.py` はこれを機械的に描画・合成するだけ。

## 大原則（CLAUDE.md 第1節と同じ）

- **根拠は記事本文だけ。** 記事に書いていない事実・数値・日付を1つも足さない
- 記事が「報道段階」「未確定」とするものは、ナレーションでも必ずそう言う
- 煽らない。ただし視聴者が対応すべき点は明確に言う

## 想定視聴者（サイトの読者より広い）

**一般視聴者向け。** ITの実務者でなくても分かるように作る（運営者の指示。2026/8/18）。

- 専門用語には初出で一言（10〜20字）の説明を挟む
  （例:「CI、つまりコードを自動でテストする仕組み」）
- サイト読者向けの前提（Laravel/AWSを業務で使っている等）を仮定しない
- ただし内容は薄めない。何が起きて、誰にどう影響するかは具体的に言う

## 構成（スライド10〜12枚、4〜5分）

| kind | 中身 |
|------|------|
| title | 「AI-news 日付」＋その日の見出し。挨拶と今日の見どころを1〜2文 |
| summary | 「今日の3行まとめ」の3点をそのまま |
| topic ×5 | 主要トピック。大衆向けに「AIと業界の大きな話」を前に出す。図版がある項目を優先して使う |
| list ×1〜2 | 残りをセクションごとに1件1文で。仕様変更・提供終了・セキュリティは落とさない。開発者にしか関係しない細かい話は削ってよい |
| outro | 「詳しくは概要欄の記事リンクへ」＋音声クレジットの読み上げ |

## ナレーション（narration）の書き方

- です・ます調。1文は短く。1スライド2〜5文、120〜200字。合計1400〜1800字
- **英語の固有名詞・略語は必ずカタカナで書く**（表示用のheading/pointsは英語のまま）。
  例: GitHub Actions→ギットハブアクションズ、AWS→エーダブリューエス、
  NVIDIA→エヌビディア、OpenAI→オープンエーアイ、Chrome→クローム
- 細かいバージョン番号（1.17.0など）は読みが崩れるのでnarrationでは言い換える
- 日本語文脈の数字はそのまま書いてよい（1050億ドル、3.3%、2027年9月30日）

## 表示テキスト（heading / points）の書き方

- headingは記事のh3を短くしたもの。全角22文字以内目安。英語はそのまま
- pointsは1スライド2〜4個、各 全角28文字以内目安
- figureは記事 `images/` の実在ファイルのみ。**-dark.png 変種を使う**（背景が濃色のため）

## JSONの形

```json
{
  "voice": { "speaker": "ずんだもん", "style": "ノーマル", "speed": 1.1 },
  "credit": "VOICEVOX:ずんだもん",
  "article": "2026-08-18_001",
  "slides": [
    { "kind": "title", "heading": "AI-news　2026/08/18", "sub": "その日の見出し", "narration": "..." },
    { "kind": "summary", "heading": "今日の3行まとめ", "points": ["…", "…", "…"], "narration": "..." },
    { "kind": "topic", "section": "セクション名", "heading": "…", "points": ["…"],
      "figure": "images/xxx-dark.png", "narration": "..." },
    { "kind": "list", "heading": "その他のニュース", "points": ["…"], "narration": "..." },
    { "kind": "outro", "heading": "今日は以上です", "narration": "..." }
  ]
}
```

## 書いたあとの検証（記事と同じ流儀で）

1. **事実**: narration・points・headingの全主張を記事本文と突き合わせる。
   書いた本人以外（fact-verifier）にやらせる
2. **読み**: narrationに英単語・記号が残っていないか。
   レンダリング後は `_video_out/<記事>/readings.json` の読み仮名を目視確認する
3. **分かりやすさ**: 一般視聴者の視点（beginner-judge）で、説明なしの専門用語を拾う
